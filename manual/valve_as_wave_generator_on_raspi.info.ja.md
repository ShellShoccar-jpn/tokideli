# valveコマンドをRaspberry Pi上で方形波発生器として使う

(English version is [here](valve_as_wave_generator_on_raspi.info.en.md))

[valve(1)](valve.man.ja.md)コマンドは「標準入力から到来したデータを、一定間隔で標準出力へ送り出す」というコマンドですが、送り先をRaspberry PiのGPIOのような実デバイスにすれば、ソフトウェアが生成したデータの並びを、そのまま実際の電気信号（パルス列）に変換できます。本ドキュメントでは、その実用性——特に方形波を発生させるパルス源としての精度——を実機で評価した記録を掲載します。

## 目的

`yes`コマンドと[valve(1)](valve.man.ja.md)コマンドの組み合わせによって発生させるパルスの品質を評価します。電気信号として利用するためのパルス源としての実用性評価と共に、UNIX（ソフトウェア）上でタイミング調節器として利用するためのパルス源としての実用性評価の材料にもします。

## 実験環境・機材

今回用いた機材は次のとおりです。

| 項目 | 値 |
|---|---|
| UNIXマシン | Raspberry Pi 3 Model B+（ARM Cortex-A53, 1.4GHz） |
| OS | Raspberry Pi OS（2021-05-07リリース、Linuxカーネル5.10.17） |
| 比較対象用パルスジェネレーター | 秋月電子 ファンクションジェネレーター FG085 |
| 計測用オシロスコープ | Hantek DSO4204B（200MHz駆動、4チャネル） |

これは、ごくありふれたUNIX環境（手頃な価格かつリアルタイムOSでもない）での品質を評価するためです。

## 実験方法

Raspberry PiとファンクションジェネレーターのGPIOの双方から同じ周波数の方形波を発生させ、それぞれをオシロスコープの別チャンネルに入力して画面上で重ね合わせます。ファンクションジェネレーターの波形を基準とし、Raspberry Pi（`valve`コマンド）側の波形がそれにどれだけピタリと重なるかを観察します。

接続は次の図のとおりです。

<p align="center">
  <img src="https://raw.githubusercontent.com/ShellShoccar-jpn/tokideli-assets/main/valve_as_wave_generator_on_raspi_fig01.png" width="480" alt="接続図: オシロスコープの2チャンネルに、ファンクションジェネレーターの出力とRaspberry PiのGPIO2をそれぞれ入力する">
</p>

Raspberry Piから送出する方形波は、次のようなワンライナーで発生させます。

```sh:
$ yes 0_1 | tr _ '\n' | valve -l Δt > /sys/class/gpio/gpio2/value
```

`yes`と`tr`コマンドによって"0"の行と"1"の行を交互に生成し、それを[valve(1)](valve.man.ja.md)コマンドに通すことによって、"0"と"1"を一定間隔（`-l`オプションで行単位出力モードを指定し、`Δt`で間隔を指定）でGPIOスペシャルファイルに書き出し、電気信号に変えます。この`Δt`に与える数値を、例えば5msにすれば100Hz（一周期10ミリ秒）の方形波になりますし、同様にして0.5msにすれば1kHzの方形波になります。

`Δt`に与える数値（生成する方形波の周波数）を変えた結果、次の3パターンでそれぞれ顕著な差が観測できたので、それぞれの様子を撮影した動画を掲載します。

| 周波数 | `Δt` | 動画 |
|---|---|---|
| 100Hz | ≒ 5ms | <https://youtu.be/e8Qx46Gbz-s> |
| 1kHz | ≒ 0.5ms | <https://youtu.be/1WZZLyjXYvg> |
| 10kHz | ≒ 50us | <https://youtu.be/a-X0ydGcugY> |

100Hzの時（`Δt`≒5ms）はほぼ綺麗に重なり続けました。1kHzの時（`Δt`≒0.5ms）も基本的には綺麗に重なり続けましたが、十数秒に一回くらいの頻度で一瞬、0.1波長程度の位相のずれが観測されました。この程度のジッターであれば、外乱としてリアルタイム制御で対処できる範囲でしょう。

しかし、10kHz（`Δt`≒50us）にすると、もはや方形波を安定して重ねることができず、絶えず時間軸方向に±0.1〜0.2波長程度ぶれ続けるようになりました。つまり、`Δt`≒50usと指定しても±10us程度の誤差が常に生じていることになり、（Raspberry Pi 3 Model B+において）再現できるタイミング精度の限界に阻まれたと言えるでしょう。

なお、ここではあえて「`Δt`=〇〇」ではなく「`Δt`≒〇〇」と記しています。これは、例えば`Δt`に5msを設定しても正確に100Hzの方形波にはならず、実際には5.003msを指定する必要があったためです。これは、Raspberry Piに搭載されている発振器の精度や個体差によるものだと思われます（低価格な発振器のクロック周期は室温の影響も受けます）。

## 考察

1kHz以上になると目視できるようになる時間軸方向への不定期の揺れ（ジッター）の主な原因は、通常のUNIX系OSがマルチユーザー・マルチタスクであるがゆえに、不定期に割り込みが入ることにあります。リアルタイムOS、RTLinuxなどはこの問題を回避するためにあると言えます。一方で、**1kHz程度までの周波数であれば、今やRaspberry Piのような安価なUNIXホストであったとしても非リアルタイムOSで一定の実用性がある**と言えるでしょう。

## まとめ

* `yes`コマンドと[valve(1)](valve.man.ja.md)コマンドを組み合わせ、Raspberry PiのGPIOスペシャルファイルに書き出すだけで、実用に足る精度の方形波（パルス列）を発生させられる。
* 100Hz〜1kHz程度までは、専用のパルスジェネレーターに匹敵するレベルの安定した波形が得られた。
* 10kHzになると、非リアルタイムOS・汎用UNIXホストというソフトウェア的制約により、±10us程度のジッターが常に生じ、安定した波形を維持できなくなる。
* したがって、[valve(1)](valve.man.ja.md)コマンドを電気信号のパルス源として、あるいはUNIX上のタイミング調節器として使う場合には、1kHz程度を実用上の目安とするのがよい。
