# DELAY(1)

(English version is [here](delay.man.en.md))

## 名前

delay - 標準入力から到来した各バイトを、一定時間だけ遅延させて標準出力に送る

## 書式

```sh:
delay [-s|-o|-d] [-v] [size@]time
delay [-s|-o|-d] [-v] controlfile
```

## 説明

標準入力から到来した各バイトを、到来した時刻から一定時間（*time*）が経過するまでリングバッファーに保持し、経過した時点で標準出力に送ります。いわゆる「遅延フィルター」です。

到来したものの、まだ保持時間が経過していないバイトは、内部のリングバッファー（*size*で指定した容量）に蓄えられます。何らかの理由でこのバッファーが満杯になった場合の挙動は、[オプション](#オプション)（`-s`/`-o`/`-d`）で選択できます。

標準入力がEOFに達した場合、このコマンドは直ちには終了しません。その時点でバッファーに残っている未出力のバイトそれぞれについて、正確に予定時刻（到来時刻+*time*）まで待ってから出力し、バッファーが空になった時点で終了します。

## 引数の説明

### time

遅延時間を指定するパラメーターです。

0以上の実数と、その直後（空白なし）に置く単位を表す文字列（省略可）とで構成されます。単位を省略した場合は秒（`s`）と見なされます。

* `s` ... 秒（デフォルト）
* `ms` ... ミリ秒
* `us` ... マイクロ秒
* `ns` ... ナノ秒
* `m` ... 分
* `h` ... 時間
* `d` ... 日

"0"を指定すると、遅延なし（到来と同時に出力）を意味します。

内部でこの値を格納するデータ型が扱える範囲を超える極端に大きな値を指定した場合はエラーになります。

### size

到来したものの、まだ出力されていないバイトを保持するリングバッファーの容量（バイト数）を指定するパラメーターです。

0より大きい実数と、その直後（空白なし）に置く単位を表す文字列（省略可）とで構成されます。単位を省略した場合はバイト（`B`）と見なされます。

* `B` ... バイト（デフォルト）
* `kB` ... キロバイト（1000倍）
* `KB` ... キビバイト（1024倍）
* `KiB` ... キビバイト（1024倍）
* `MB` ... メガバイト（1000^2倍）
* `MiB` ... メビバイト（1024^2倍）
* `GB` ... ギガバイト（1000^3倍）
* `GiB` ... ギビバイト（1024^3倍）

バイト単位に換算した結果が整数にならない場合は、小数点以下を切り捨てます（例えば"0.1KiB"なら102.4バイトなので102バイトになります）。切り捨てた結果0バイトになった場合はエラーになります。

*time* との境界を区別するため、*size* パラメーターの直後には必ず文字`@`を付けてください。省略した場合は"1MiB"が指定されたものと見なします。

動作しているコンピューターが搭載している総物理メモリ量の80%以上に相当するサイズを指定した場合はエラーになります。

ただし、ここでいう80%は、*size* に指定した値そのものと比較しているのではなく、このコマンドが内部的に実際に確保するメモリ量と比較しています。リングバッファーは、保持する1バイトごとに、そのバイトが到来した時刻を記録するための領域も併せて確保するため、実際のメモリ使用量は *size* に指定した値そのものよりもかなり大きくなります。目安として、一般的な64ビット環境では、1バイトを保持するために実際には約24バイトのメモリが使われるため、指定できる *size* の実質的な上限は、搭載メモリ量の80%ではなく、その1/24程度（おおむね3〜4%程度）になります。この倍率は、OSやCPUアーキテクチャー（32ビット環境か64ビット環境か等）によって変動します。

### controlfile

前述の`[size@]time`を動的に設定するためのファイル（*controlfile*）を指定します。

この位置に指定した文字列が`[size@]time`の書式に該当しなかった場合、その名前の*controlfile*が指定されたものと見なします。数字だけのファイル名など、書式と被る恐れがある名前のファイルを使いたい場合は、`./1`のようにパス付きで指定してください。

*controlfile* を使う場合、`[size@]time`の書式とは異なり、*time* の指定を省略できます。すなわち、受け入れ可能な書式は`{time|size@time|size@}`です（`size@`のみを書けば、sizeだけを更新し、timeは変更しないという意味になります）。

*controlfile* からまだ一度も有効なパラメーターを読み取れていない場合の初期値は、time=0、size=1MiBです。

読み取った1行分の文字列が上記の書式に該当し、それぞれの値が正当であれば、その都度パラメーターを再設定します。書式に該当しない場合や値が不正な場合はエラーにせず、静かに無視します。timeとsizeの両方が指定されていた場合は、両方とも正当な値でなければ、その行全体を無視します（例えば`size@time`の`size`部分だけが正しく`time`部分が不正なら、`size`の変更も行われません）。

*controlfile* として使えるファイルは、名前付きパイプなどのキャラクタースペシャルファイル、または通常ファイルです。

#### 通常ファイル

*controlfile* として通常ファイルを用いる場合、新しいパラメーターは必ず **新規作成モード（`O_CREAT`や`>`）** で書き込んでください。追記モード（`O_APPEND`や`>>`）で書き込んではいけません。理由は、通常ファイルの場合、このコマンドは常にファイルの先頭を監視するからです。

監視は0.1秒間隔で行われます。もし、書き込んだ新しいパラメーターを直ちに反映したいのであれば、ファイルを更新した後でこのコマンドに対してSIGHUPを送ってください。

#### キャラクタースペシャルファイルまたは名前付きパイプ

*controlfile* としてこれらのいずれかを用いる場合、書き込むモードは上記のどちらでも構いません。また、書き込んだ内容（1行分）は直ちに反映されますのでシグナルを送る必要はありません。

パフォーマンスの観点からすると、通常ファイルよりこちらの方が有利です。

## オプション

### -s, -o, -d

リングバッファーが満杯になった状態で新しいバイトが到来した場合の挙動を指定します。三つは互いに排他的であり、複数指定した場合は最後に指定したものが有効になります。

* `-s` ... （デフォルト）suspend。バッファーに空きができるまで、標準入力からの読み込みを一時停止（ブロック）します。
* `-o` ... overwrite。最も古い未出力のバイトを破棄し、新しいバイトで上書きします。
* `-d` ... disconnect。バッファーの内容を一切出力せず、このコマンド全体を直ちに終了します。

### -v

冗長モードレベルを1つずつ上げます。`-v`ならレベル1、`-vv`ならレベル2とし、レベルが高いほど内部動作を詳細に標準エラー出力へ実況します。

レベル1では、少なくともバッファーが満杯になった（溢れた）際に、そのことと今回の対応（一時停止・上書き・切断のいずれか）を毎回報告します。

### -h

Usageや最終更新日、ライセンスなどを標準エラー出力に表示します。

## 戻り値

標準入力がEOFに達し、バッファーの内容をすべて出力し終えて正常終了した場合は0を返します。`-d`オプションの効果によりバッファー満杯を理由に強制終了した場合は1を返します。それ以外の異常終了（引数エラーなど）の場合は0以外を返します。

## 使用例

到来した各バイトを1秒遅らせて出力する。（デフォルト設定により、バッファーに入りきらないデータはバッファーが空くまでブロックされるので、データが大量でも消失せずに、1秒遅れで出力される）

```sh:
$ cat file | delay 1s
```

[typeliner(1)](typeliner.man.ja.md)コマンドでキーボードからのタイプを1文字単位で出力するようにしつつ、その様子をリアルタイムで出力するとともに、3秒遅れでも出力し、山びこのようにする。

```sh:
$ typeliner -t "" | (tee /dev/stderr | delay 3s) 2>&1
yo-ho!⏎        ← 3秒以内に"yo-ho!"と[Enter]キーをタイプする。
yo-ho!          ← 3秒後に、同じタイプタイミングで"yo-ho!"が表示される。
$ 
```

さらに、山びこの数を倍にする。

```sh:
$ typeliner -t '' | (( tee /dev/stderr | delay 3 ) 2>&1 | tee /dev/stderr | delay 6) 2>&1
yo-ho!⏎        ← 3秒以内に"yo-ho!"と[Enter]キーをタイプする。
yo-ho!          ← 3秒後に、同じタイプタイミングで"yo-ho!"が表示される。
yo-ho!          ← 6秒後に、同じタイプタイミングで"yo-ho!"が表示される。
yo-ho!          ← 9秒後に、同じタイプタイミングで"yo-ho!"が表示される。
$ 
```

MQTT経由で到来するデータを[mosquitto_sub(1)](https://mosquitto.org/man/mosquitto_sub-1.html)コマンドで受信し、それをパイプ経由で"COMMAND1"に送り処理をさせたい。しかし、時々、COMMAND1の処理能力を超えた速度でデータが到来し、そのままでは取りこぼす恐れがある。そこで、delayコマンドを仲介させ、1メビバイト分の入力データを保持するのに必要な量のバッファーを確保しつつ、遅延は無しで出力する。こうすることで1メビバイトまではMQTTデータを取りこぼさないように対策をする。もし、それでもバッファーが溢れてしまった場合には、エラー終了して、処理を中断する。（ただし、遅延0固定で使うのであれば、[surgetk(1)](surgetk.man.ja.md)を使うべきである）

```sh:
$ mosquitto_sub -t MY_TOPIC -h BROKER | delay -d 1MiB@0 | COMMAND1
```

名前付きパイプ`ctrl`を介して、動作中に遅延時間とバッファーサイズを変更できるようにする。

```sh:
# 端末1での操作
$ mkfifo ctrl
$ cat file | delay ctrl > result

# 端末2での操作
$ echo '1MiB@2s' > ctrl  ⏎  ← バッファー1MiB・遅延2秒に設定
$ echo '500ms' > ctrl    ⏎  ← 遅延時間だけを500ミリ秒に変更（バッファーサイズは変更しない）
```

## バグ

*time* にはナノ秒単位までの遅延時間を指定できますが、実際にその精度の遅延時間が作り出せるとは限りません。どれくらい高精度な遅延時間を実現できるかはOSの状態やハードウェアの性能に依存します。（同種の考察として、[valveコマンドの転送レート精度に関するレポート](valve_precision.info.ja.md)も参照してください。）
