# TYPELINER(1)

（日本語版は[こちら](typeliner.man.ja.md)）

## Name

typeliner - outputs each character typed at the terminal immediately, with a newline appended

## Synopsis

```sh:
typeliner [options]
```

## Description

Normally, characters typed at a terminal stay in the input queue (a buffer separate from the one provided by stdio.h) and are only sent to standard output as a group once the [Enter] key is pressed. This command changes that: each keystroke is sent to standard output immediately. A newline is appended right after the character (except when the typed key was [Enter] itself). This lets each typed character be processed in real time by most other line-oriented UNIX commands or shell scripts (once full-buffering has been disabled with something like stdbuf(1) or [ptw(1)](ptw.man.en.md)).

Because of this behavior, it makes no sense to use this command with its input side not connected to a terminal. Specifically, this includes:

* Using this command in the middle of a command pipeline
* An environment where isatty(2) on standard input returns 0
* A case where running `[ -t 0 ]` with the test(1) command returns non-zero

In such cases, the command still runs, but it just ends up behaving like cat(1), forwarding whatever arrives on standard input to standard output.

Note that when multiple characters arrive at once (for example, via copy & paste), they are treated as a single "character," with only one newline appended after all of them.

Each option is explained separately below.

## Options

### -1

After starting up, this command receives one character of keyboard input, sends it to standard output with a newline appended, and exits immediately. This is the same as using the -n option as `-n 1`. It can be convenient as a replacement for the `read` built-in command of sh(1): `read` does not assign the typed string to a shell variable until [Enter] is pressed, but with this command you can capture what was typed into a shell variable immediately, without waiting for [Enter]. (See the "Examples" section.)

Here, a "character" means one unit typed at the terminal; if multiple characters arrive at once (e.g. via copy & paste), they are counted as one. Also, this option only has an effect when this command's input side is a terminal (otherwise it is ignored).

### -d

Disables special handling of the EOT character generated by [Ctrl]+[D]. UNIX commands generally stop accepting keystrokes when [Ctrl]+[D] is typed, and this command is no exception by default. With this option, that behavior is turned off, and EOT is treated like any other character, with its character code 0x04. Use this if you want to be able to type EOT itself.

This option only has an effect when this command's input side is a terminal (otherwise it is ignored).

### -e

Enables local echo. For instance, in the first example below the characters you type are not shown on the screen, but in the second example they are.

```sh:
$ typeliner > mytyping.txt
$ typeliner -e > mytyping.txt
```

This option only has an effect when this command's input side is a terminal (otherwise it is ignored).

### -n *num*

After starting up, this command receives *num* characters of keyboard input, sends them to standard output with a newline appended, and exits immediately. Using it as `-n 1` is the same as the -1 option.

Here, a "character" means one unit typed at the terminal; if multiple characters arrive at once (e.g. via copy & paste), they are counted as one. Also, this option only has an effect when this command's input side is a terminal (otherwise it is ignored).

### -t *str*

Normally, when a typed character is written to standard output, a newline is appended at the end; this option replaces that with the string defined by *str*. For example, `typeliner -t ,` produces comma-separated output. Also, `typeliner -t ""` (an empty string) writes each character you type on the keyboard to standard output in real time, one character at a time (rather than one line at a time).

This option only has an effect when this command's input side is a terminal (otherwise it is ignored).

## Return Value

Returns 0 only when processing finished normally, e.g. via the -1 or -n option, or by pressing [Ctrl]+[D]. Returns non-zero if the argument or an option was invalid, or if the command was interrupted, e.g. with [Ctrl]+[C].

## Examples

Wait for one character to be typed on the keyboard, and assign what was typed to the shell variable `confirm` immediately. (Unlike the `read` command, there's no need to press [Enter].)

```sh:
printf 'Are you sure? (Y/N): '
confirm=$(typeliner -1e)
```

Send each character typed on the keyboard to the next command ("COMMAND1") in real time, one character at a time (rather than one line at a time).

```sh:
$ typeliner -t "" | COMMAND1
```

Record your own typing using this command together with [linets(1)](linets.man.en.md), and then play it back.

```sh:
$ typeliner -e | linets -3 > mytyping.txt
(after typing some characters, press [Ctrl]+[D] at the end)
$ tscat -yZ mytyping.txt
(your typing is now replayed on the screen)
```

## Compliance with Standards

The source code of this command is written to conform to C99 and IEEE Std 1003.1-2008 ("POSIX.1").
