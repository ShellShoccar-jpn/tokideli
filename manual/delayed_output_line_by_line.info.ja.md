# 行単位でデータを遅延出力する方法

(English version is [here](delayed_output_line_by_line.info.en.md))

[delay(1)](delay.man.ja.md)コマンドは、到来した1バイトごとにタイムスタンプを記録し、バイト単位で出力を遅延させるコマンドです。しかし、改行で区切られたテキストデータに対しては、「バイト単位」ではなく「行単位」で遅延出力をさせたい場面もあります。本ドキュメントでは、その実現方法と、実現にあたって注意すべき点について説明します。

## 「行単位」の遅延出力は厳密には不可能であることに注意

「行単位」で出力するということは、出力する時点で1行分のテキストデータが一斉に出力されることを意味します。しかし、入力される時点では、1行分のデータが必ずしも一斉に到来するとは限りません。また、1行分のテキストデータを完全に受け取り終えるまでは、その行を出力することはそもそもできません。

したがって、たとえば、各行を先頭から末尾まで送るのに5秒かかるようなデータ源に対して、各行の出力をその先頭到来時刻から1秒だけ遅らせる、ということは不可能です（1秒後の時点では、まだその行は半分も到来していないため、出力しようにも出力するものがありません）。

よって、本ドキュメントにおける以降の議論は、**各行のテキストデータが先頭から末尾まで到来するのに要する時間が、実現したい遅延時間よりも十分短いこと**を前提とします。

### 到来がゆっくりなデータへの対処

もし、ゆっくり流れてくるテキストデータ源に対して、行末の到来時刻を基準に遅延させたい場合は、無害なgrepコマンド（および可能であればstdbuf(1)コマンド）を経由させることで、各行の行末が到来したタイミングで行全体が一斉に出力されるように調整したうえで、以降の処理に入力するとよいでしょう。

* stdbuf(1)コマンドが使える場合
  ```sh:
  $ cat SLOW_TEXTDATA_SOURCE | stdbuf -o L grep ""
  ```
* stdbuf(1)コマンドが使えない場合は、[ptw(1)](ptw.man.ja.md)コマンドを使うとよいでしょう。
  ```sh:
  $ cat SLOW_TEXTDATA_SOURCE | ptw grep ""
  ```

## delay(1)で行単位に遅延出力する

各行のテキストデータが十分速く到来するという前提のもとでは、単純に[delay(1)](delay.man.ja.md)コマンドへテキストデータを流すだけで、行単位の遅延出力が実現できます。例えば、各行の出力を3秒遅らせて出力するには次のように書きます。

```sh:
$ cat TEXTDATA_SOURCE | delay 3s
```

データの転送速度が速く、遅延のために保持しておくバッファーが大きく必要になると想定される場合は、バッファーを多めに確保してください。例えば、到来データ10MiB分のバッファーを確保するには次のように書きます。

```sh:
$ cat TEXTDATA_SOURCE | delay 10MiB@3s
```

### メモリ消費を抑えたい場合

ただし、[delay(1)](delay.man.ja.md)コマンドはもともとバイト単位の遅延を想定しており、1バイトごとにタイムスタンプ記録用の領域も確保します。このタイムスタンプがナノ秒精度であるという事情から、64ビット環境の場合、1バイトを保持するために実際には16バイトのメモリが確保されます（詳細は[delay(1)コマンドのsize引数の説明](delay.man.ja.md#size)を参照してください）。そのため、大きなバッファーを確保しようとすると、その分メモリを大量に消費してしまいます。

これを避けたい場合は、代わりに[surgetk(1)](surgetk.man.ja.md)・[linets(1)](linets.man.ja.md)・[tscat(1)](tscat.man.ja.md)の各コマンドと、awk(1)コマンドを組み合わせ、次のように書くとよいでしょう。

```sh:
$ cat TEXTDATA_SOURCE |
  linets -6e          |
  surgetk 1MiB        |
  awk -v dt=3.0 '
    BEGIN {
      OFMT="%.6f"; OFS="";
      while (getline l) {
        i=index(l," ");
        print substr(l,1,i-1)+dt, substr(l,i);
        fflush();
      }
    }'                |
  tscat -e
```

仕組みを簡単に説明します。まず[linets(1)](linets.man.ja.md)コマンドで、到来した各行に速やかにタイムスタンプを付けます。このとき、後で単純な加減算ができるように、UNIX時間形式（`-e`）のタイムスタンプにしておくのがポイントです。その直後に[surgetk(1)](surgetk.man.ja.md)コマンドでバッファーを確保しておきます。このバッファーが十分な大きさであれば、後続のコマンド側の処理が一時的に遅れても、その影響で[linets(1)](linets.man.ja.md)コマンドが入力をブロックしてしまう事態を防げます。続くawk(1)コマンドで各行先頭のタイムスタンプに3秒を加算し、それを[tscat(1)](tscat.man.ja.md)コマンドに渡せば、各行はその加算された時刻に出力されます。

## バッファーサイズの決め方

[delay(1)](delay.man.ja.md)・[surgetk(1)](surgetk.man.ja.md)コマンドに指定するバッファーサイズ（*size*引数）の目安を決めるために、各パラメーターを次のように定義します。

* 入力されるテキストデータの1行あたりの平均バイト数を*sl*
* 1秒あたりに到来する行数を*nl*
* 遅延させたい秒数を*dt*

この場合、遅延出力のために保持しておかなければならないデータのバイト数*sb*（＝[delay(1)](delay.man.ja.md)/[surgetk(1)](surgetk.man.ja.md)コマンドの*size*パラメーターに指定すべき最低値）は、次の式で計算できます。

```
sb = sl * nl * dt
```

したがって、例えば1行あたり81バイトで毎秒平均50行が到来し、それらを3秒遅延させたい場合、*sb*=12150（約12KiB）になります。

あるいは、入力データの転送速度が*r*bpsである場合、*sb*は次のように計算できます。

```
sb = ( r / 8 ) * dt
```

よって、例えば57600bpsの通信路で到来するデータを5秒間遅延させたい場合、*sb*=36000（36kB）になります。

補足:

* これらの見積もりは理論値であり、実際には転送速度の揺らぎによってこれを上回ることがあるので、若干多めに確保しておく方が安全です。
* [delay(1)](delay.man.ja.md)コマンドに指定した場合、内部ではその16倍（64ビット環境の場合）のメモリ領域を確保しようとするので、ホストの搭載メモリ量に注意が必要です（前述のとおり、[surgetk(1)](surgetk.man.ja.md)コマンドの場合はこの倍率は発生しません）。

## まとめ

行単位でのテキストデータの遅延出力は、各行の到来に要する時間が遅延時間より十分短いという前提のもとでなら、[delay(1)](delay.man.ja.md)コマンド単体で簡単に実現できます。大きなバッファーが必要になりメモリ消費が気になる場合は、[linets(1)](linets.man.ja.md)・[surgetk(1)](surgetk.man.ja.md)・[tscat(1)](tscat.man.ja.md)とawk(1)を組み合わせた方法で、バイト単位のタイムスタンプ記録コストを避けながら同じ効果を得られます。どちらの方法を選ぶかは、想定するデータ量とホストのメモリ事情に応じて判断してください。
