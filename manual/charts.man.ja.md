# CHARTS(1)

(English version is [here](charts.man.en.md))

## 名前

charts - ロケールに応じた1文字ごとにタイムスタンプを付加して出力

## 書式

```sh:
charts [-0|-3|-6|-9] [-c|-e|-I|-z|-Z] [-1bdu] [file [...]]
```

## 説明

テキストファイルであるfileから、ロケールに応じた1文字（"C"/"POSIX"ロケールでは1バイト、UTF-8のようなマルチバイトロケールでは複数バイトの場合もある）を読み込み、その文字を読み込んだ時刻をタイムスタンプとして先頭に付加しつつ、それを1つのレコードとして出力します。これは、同じことを行単位で行う[linets(1)](linets.man.ja.md)の、文字単位版にあたる姉妹コマンドです。

デフォルトでは、現在のロケール（`setlocale(LC_CTYPE, "")`）に従い、`mbrtowc()`を用いて1文字が何バイトで構成されるかを判定します。`-b`オプションを指定した場合は、ロケールを一切無視して常に1バイト=1文字として扱います（後述の[-b](#-b)オプションを参照）。

本コマンドが出力する各レコードは末尾に改行を付加しますが、**その文字自体がちょうど1バイトの`\n`だった場合は、改行を追加しません**（その文字自身のバイトが、すでにレコードの終端として機能するため。詳細は後述の[レコード形式と改行省略ルール](#レコード形式と改行省略ルール)を参照）。この仕様により、出力は完全に可逆（ロスレス）になります。つまり、全レコードの文字部分（ペイロード）を順番に連結すれば、改行の位置も含めて元のバイト列を完全に復元できます。

タイムスタンプの精度（秒単位からナノ秒単位まで）やフォーマット（カレンダー時間やUNIX時間など）、さらに前の文字との差分も付加するかなどは、[linets(1)](linets.man.ja.md)と同様にオプションで切り替えられます。

## 引数の説明

### file

データ源となるファイル。省略したり、`-`を指定した場合には標準入力と見なされます。複数指定することも可能です。

## オプション

### -0, -3, -6, -9

付加するタイムスタンプの精度を指定します。-0、-3、-6、-9はそれぞれ、秒単位、ミリ秒単位、マイクロ秒単位、ナノ秒単位を意味し、それぞれのオプションは互いに排他的です。これらがいずれも指定されなかった場合には-0が指定されたものと見なします。

また、-dオプションを併用していた場合には、それによって付加される前文字出力時刻からの経過秒数についても同じ精度が適用されます。

### -c, -e, -I, -z, -Z

タイムスタンプのフォーマットを指定します。-c、-e、-I、-z、-Zはそれぞれ、カレンダー時間、UNIX時間、拡張ISO 8601形式、本コマンド起動時からの経過秒数、テキストデータの先頭文字到来時刻からの経過秒数を意味し、それぞれのオプションは互いに排他的です。これらがいずれも指定されなかった場合には-cが指定されたものと見なします。

それぞれのバイト単位でのフォーマットの詳細は、[linets(1)](linets.man.ja.md)の対応するオプションと全く同一です（「行」を「文字」と読み替えてください。例えば-Zの経過秒数は、テキストデータの先頭「行」ではなく先頭「文字」の到来時刻から測られます）。

### -1

コマンド起動時、標準入力からのデータとは関係の無い1行（LF）を出力します。このオプションの目的は、AWKやシェルスクリプトからこのコマンドと双方向パイプを構築する際、デッドロックが起こるのを防ぐためです（[linets(1)](linets.man.ja.md)の-1オプションと全く同じ目的・動作です）。

### -b

バイトモードを強制します。現在のロケールに関わらず、常に1バイトを1文字として扱います。このモードでは、`setlocale()`や`mbrtowc()`を一切呼び出しません。このオプションには2つの目的があります。

* **明確さ** — ロケールについて詳しく知らなくても（あるいは自分で`LC_ALL=C`を設定しなくても）、`-b`と明示するだけで確実に1バイト単位の処理になります。
* **速度** — ロケール判定・`mbrtowc()`処理を一切行わないため、計測可能な速度向上が見込めます。入力が単純なASCIIであると分かっている場合や、そもそもマルチバイト境界を気にしない用途で有用です。

### -d

1列目のタイムスタンプの後に2列目として、前の文字の到来時刻からの経過秒数を挿入します。[linets(1)](linets.man.ja.md)の-dオプションと全く同じ動作です（「行」を「文字」と読み替えてください）。

### -u

タイムゾーンをUTCに設定します。[linets(1)](linets.man.ja.md)の-uオプションと同じです。

## レコード形式と改行省略ルール

本コマンドが出力する各レコードは、次の形式です。

```text:
TIMESTAMP <その1文字の生バイト>
```

このあとに改行が付加されますが、**その文字の生バイトがちょうど1バイトの`\n`だった場合に限り**、追加の改行は付加されません。その文字自身のバイトが、すでにそのレコードを終端しているためです。

例えば、2行からなるUTF-8テキスト「こんにちは、\n世界!\n」を、マイクロ秒精度でUTF-8ロケールで本コマンドに通すと（`printf`の出力はパイプを通して一瞬でまとめて到着するため、文字同士の間隔はこのくらいの精度でなければ見えてきません。ミリ秒精度では全て同じ値に見えてしまいます）、

```sh:
$ printf 'こんにちは、\n世界!\n' | LC_ALL=ja_JP.UTF-8 charts -6e
1791201867.431638 こ
1791201867.431651 ん
1791201867.431913 に
1791201867.431919 ち
1791201867.431924 は
1791201867.431929 、
1791201867.431934 
1791201867.431939 世
1791201867.431944 界
1791201867.431949 !
1791201867.431954 
```

ちょうど11レコード出力されます（文字数ぶん＝2つの`\n`自身も1レコードとして数えられ、それぞれ「タイムスタンプの後に何も続かない」形で表示されます。それは、その文字自身のバイトがすでにその行を終端しているからです）。空行や二重の改行はどこにも生じません。この11レコードの文字部分（ペイロード）を順番に連結すると——こ＋ん＋に＋ち＋は＋、＋（1つ目の`\n`）＋世＋界＋！＋（2つ目の`\n`）——元の入力と完全に一致します。

## 不正なバイト列

入力に、現在のロケールで解釈できないバイト列（`mbrtowc()`がエンコーディングエラーを報告するケース）が含まれていた場合、本コマンドは標準エラーに警告を出し、そのバイト列の先頭1バイトだけを単独の1文字として（生のまま）出力し、次のバイトから読み込みを再開します。1バイトの不正値だけでコマンド全体を異常終了させることはないため、長時間稼働するパイプの途中でたまに壊れたデータが混入しても処理は継続されます。

```sh:
$ printf 'AB\xffCD\n' | LC_ALL=ja_JP.UTF-8 charts -e
charts: an invalid byte (0xff) was replaced with a 1-byte character
1700000000 A
1700000000 B
1700000000 （生の0xffバイトがそのまま出力される）
1700000000 C
1700000000 D
1700000000 
```

このような警告が、本来正しいはずのマルチバイトテキストの全バイトに対して1つずつ、延々と連続して出てくる場合によくある原因は、**そのシステムに実際には存在しない（生成されていない）ロケールを指定してしまっていること**です（例：`ja_JP.UTF-8`というロケールが一度も生成されていない環境で`LC_ALL=ja_JP.UTF-8`を指定した場合）。この場合、`setlocale()`はエラーを起こさず静かに失敗し、ロケールは`"C"`のままになりますが、`"C"`ロケールでは0x7Fを超えるバイトに対応する文字が一切定義されていません。本コマンドは`setlocale()`の失敗を検出すると、個々のバイトに関する警告よりも先に、この問題について専用の警告を出します。この警告が出た場合は、入力データそのものが壊れていると決めつける前に、実際に利用可能なロケール（`locale -a`で確認できます）を確認してください。

```sh:
$ LC_ALL=ja_JP.UTF-8 charts -e < kanji.log
charts: failed to set the locale requested via LC_ALL/LC_CTYPE/LANG; falling back to the "C" locale, so multibyte characters will be reported as invalid bytes. Install/generate the requested locale, or specify one that is actually available (see: locale -a), or use -b if byte-mode processing is what you actually want.
charts: an invalid byte (0xe3) was replaced with a 1-byte character
  :
```

## 末尾の不完全な文字

マルチバイト文字の途中で入力ストリームがEOFを迎えた場合（文字を完成させるのに必要なバイト数が足りない場合）、本コマンドは標準エラーに警告を出し、残っている不完全なバイト列を最後の1レコードとしてそのまま出力したうえで、通常のEOFと同様に終了コード0で終了します。

```sh:
$ printf 'AB\xe3\x81' | LC_ALL=ja_JP.UTF-8 charts -e
charts: an incomplete multibyte character (2 byte(s)) was cut off by EOF; flushing it as the last character
1700000000 A
1700000000 B
1700000000 （残った2バイトがそのまま出力される）
```

## 戻り値

指定されたすべてのファイルを正常に処理できた場合にのみ0を戻し、引数・オプションが不正であった場合や一つでもファイル処理に失敗した場合には0以外を戻します。

## 使用例

UTF-8の日本語ログファイルに、ミリ秒単位までのカレンダー時間タイムスタンプを、1文字ごとに付加する。

```sh:
$ LC_ALL=ja_JP.UTF-8 charts -3 < kanji.log
```

同じファイルを、高速なパスを使いたい、あるいはマルチバイト境界を気にしない用途のために、バイト単位で処理する。

```sh:
$ charts -b -3 < kanji.log
```

ユーザーが端末にキー入力するたびに、その到来時刻を正確に記録する。これは[typeliner(1)](typeliner.man.ja.md)（個々に入力された文字の集まりを1行にまとめる、逆方向の処理を行うコマンド）と自然に対をなす使い方です。

```sh:
$ some_keystroke_source | charts -9e
```

出力が完全に可逆（ロスレス）であることを確認する。各レコードから"TIMESTAMP "の部分を取り除き、残りを連結する（レコードのペイロード自体が`\n`だった箇所にのみ改行を加える）ことで、元のファイルと完全に一致することを確認できる。

```sh:
$ charts -e < orig.txt |
  awk '{ sub(/^[0-9.]+ /, ""); if ($0=="") printf "\n"; else printf "%s", $0 }' |
  diff - orig.txt && echo "lossless"
```

記録した文字を、当時のタイミングを再現しながら再生する。これには[tscat(1)](tscat.man.ja.md)の`-y`オプション（「タイピングモード」）を使う。`-y`は、通常各レコードの後に付加する改行を抑制するが、レコードのペイロードが空である場合に限り抑制しない——これは、前述の[レコード形式と改行省略ルール](#レコード形式と改行省略ルール)で説明した、`charts`が改行文字そのものを表すレコードを出力する際の形そのものである。したがって、`charts`の出力をそのまま`tscat -y`（絶対時刻の到来を待つのではなく先頭文字からの相対時間で再生させる`-Z`も併用する）に渡せば、元のテキストと、文字間の時間間隔の両方が復元される。

```sh:
$ some_keystroke_source | charts -3e > recorded.txt
$ tscat -ey -Z < recorded.txt
```

## バグ

コマンド自体はナノ秒単位まで表示しますが、その時刻が正確とは限りません。どれくらい正確かはOSの状態やハードウェアの性能に依存します。

マルチバイト文字のデコード（-bを指定しない場合）は、プラットフォームの`mbrtowc()`・ロケール実装に依存します。

## 規格への準拠

このコマンドのソースコードはC99、IEEE Std 1003.1-2008（“POSIX.1”）に準拠させてあります。
