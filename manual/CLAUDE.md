# manual ディレクトリのドキュメント作成ガイド

このディレクトリには `c_src/` の各コマンドに対応するユーザー向けマニュアル（`<コマンド名>.man.ja.md`）や、日英両方が揃っている読み物系ドキュメント（`ptw.info.{ja,en}.md`, `linets_and_tscat.{ja,en}.md` など）が置かれている。

## 日英ドキュメント間の相互リンクの言語

日本語版・英語版が対になっているドキュメントの冒頭には、もう片方の言語版へのリンクを置く（例: `manual/ptw.info.ja.md:5`, `manual/ptw.info.en.md:5`）。このリンクの**案内文の言語は、今読んでいるドキュメント自身の言語ではなく、リンク先のドキュメントの言語で書く**こと。

```
ptw.info.ja.md（日本語ドキュメント）:
  (English version is [here](ptw.info.en.md))   ← 英語で書く

ptw.info.en.md（英語ドキュメント）:
  （日本語版は[こちら](ptw.info.ja.md)）        ← 日本語で書く
```

**理由**: このリンクの主な想定読者は、検索エンジン等で誤って自分の読めない言語のページに辿り着いてしまった人である。例えば英語話者が誤って日本語版ページを開いてしまった場合、「英語版はこちら」という日本語の案内文は読めないため役に立たない。案内文を常にリンク**先**の言語（＝その案内を必要としている読者が読める言語）で書くことで、案内自体が読者に伝わるようにしている。

一見すると「自分の言語で書く」（＝自己言語ラベル）の方が自然に見えるが、それは誤り。過去に一度、良かれと思ってこの逆（自己言語ラベル）に「統一」してしまった失敗があるので注意すること。判断に迷ったら、両言語版を実際に開いて、逆方向のリンクの言語がどうなっているかを確認してから合わせること。

## 相互リンクの位置

このリンクは、タイトル（`# ...`見出し）の直後、本文の導入文よりも前に置く（例: `manual/rec_baby_typing.info.ja.md:1-5`）。`*.man.{ja,en}.md`は元々タイトル直後に「## 名前」/「## Name」セクションが続く構成なのでこの位置に自然と収まるが、`*.info.{ja,en}.md`や`linets_and_tscat.{ja,en}.md`のような読み物系ドキュメントでは、導入の地の文を書いた後にリンクを置いてしまいがちなので注意すること。

**理由**: 言語を誤って開いてしまった読者が、本文を読み進める前の最初の一行で正しい言語版に気づけるようにするため。導入文の後にリンクがあると、読めない言語の文章を少し読んでから初めて気づくことになり、案内としての効果が薄れる。

## 関連ドキュメントへのリンクは地の文か、末尾の「関連項目」か

`*.man.{ja,en}.md`は元々末尾に「## 関連項目」/「## See Also」セクションを持つ（man(1)の伝統的な構成に準拠）。これに対し`*.info.{ja,en}.md`のような読み物系ドキュメントでは、次のように使い分けること。

* **地の文（本文中）にリンクを置く**: 説明の流れの中で実際に使っている・言及しているコマンドやドキュメントへの言及（例: 「[delay(1)](delay.man.ja.md)コマンドは…」のように、そのコマンド自体が話題になっている箇所）。これまでの`*.info.{ja,en}.md`は一貫してこの形式を採っている（例: `valve_precision.info.ja.md`）。
* **末尾に「## 関連項目」/「## See Also」セクションを設けてそこに置く**: 同じコマンドを別の角度から扱う姉妹ドキュメントへの相互リンクなど、本文の流れの中に自然に差し込める箇所がなく、無理に地の文へ埋め込むと唐突になってしまうもの（例: `valve_precision.info.ja.md`と`valve_as_wave_generator_on_raspi.info.ja.md`は、互いに「関連項目」セクションで相互リンクしている）。

**理由**: 文脈があるところにリンクを置いた方が読みやすい一方、文脈のない「さらに読む」的な関連ドキュメントを無理に地の文に挟み込むと、話の流れを損ねてしまう。man形式の「関連項目」という使い慣れた型をinfoドキュメントにも転用することで、両者を自然に書き分けられる。
