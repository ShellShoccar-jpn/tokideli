# SURGETK(1)

(English version is [here](surgetk.man.en.md))

## 名前

surgetk - サージタンク：標準入力への一時的なバースト流入をバッファーに吸収し、標準出力へ平滑に送る

## 書式

```sh:
surgetk [-s|-o|-d] [-v] [-m fd|file] size
surgetk -i
```

## 説明

標準入力から到来した各バイトを、いったんリングバッファー（容量は*size*で指定）に保持したうえで、標準出力に送ります。標準入力から一時的に高い流量でデータが到来しても、リングバッファーに溜め込むことで吸収し、標準出力側の処理速度に合わせて滑らかに送り出せます。名前の由来は、配管やポンプの脈動を吸収するために設置される「サージタンク」という設備です。

このコマンドは、[delay(1)](delay.man.ja.md)コマンドの*time*パラメーターを常に0に固定した動作に相当します。到来したバイトを意図的に遅延させることはせず、標準出力側が受け取れる状態になり次第、直ちに送り出します。そのため、*time*に相当するパラメーターは存在しません。

到来したものの、まだ出力されていないバイトを保持しきれずリングバッファーが満杯になった場合の挙動は、[オプション](#オプション)（`-s`/`-o`/`-d`）で選択できます。

標準入力がEOFに達した場合、このコマンドは直ちには終了しません。その時点でバッファーに残っている未出力のバイトをすべて出力し終えてから終了します。

## 引数の説明

### size

到来したものの、まだ出力されていないバイトを保持するリングバッファーの容量（バイト数）を指定するパラメーターです。省略できません。

0より大きい実数と、その直後（空白なし）に置く単位を表す文字列（省略可）とで構成されます。単位を省略した場合はバイト（`B`）と見なされます。

* `B` ... バイト（デフォルト）
* `kB` ... キロバイト（1000倍）
* `KB` ... キビバイト（1024倍）
* `KiB` ... キビバイト（1024倍）
* `MB` ... メガバイト（1000^2倍）
* `MiB` ... メビバイト（1024^2倍）
* `GB` ... ギガバイト（1000^3倍）
* `GiB` ... ギビバイト（1024^3倍）

バイト単位に換算した結果が整数にならない場合は、小数点以下を切り捨てます（例えば"0.1KiB"なら102.4バイトなので102バイトになります）。切り捨てた結果0バイトになった場合はエラーになります。

動作しているコンピューターが搭載している総物理メモリ量の80%以上に相当するサイズを指定した場合はエラーになります（[delay(1)](delay.man.ja.md)と異なり、このコマンドのリングバッファーは1バイトの保持につき実際に1バイトのメモリしか消費しないため、*size*に指定した値をそのまま搭載メモリ量と比較しています）。

#### sizeを小さくすることの意味について

`cmd0 | surgetk size | cmd1`のようにこのコマンドをパイプラインに挟んだ場合、データが通過する経路には、実は*size*以外にも複数の緩衝地帯（バッファー）が直列に存在します。

1. cmd0からsurgetkへのカーネルパイプ（OSが持つ）
2. surgetkの標準入力側のstdioバッファー（libcが持つ）
3. surgetk自身のリングバッファー（*size*で指定する部分）
4. surgetkからcmd1へのカーネルパイプ（OSが持つ）

このうち1・2・4は、*size*の値によらず、OSとCの標準ライブラリが最初から確保している「無料の」緩衝地帯です。しかも、`cmd0 | cmd1`のように直接繋いだ場合にはパイプが1本しか存在しませんが、間にこのコマンドを挟むこと自体によって新たにもう1本のカーネルパイプ（上記4）が生じるため、*size*をどんな値にしようとも、このコマンドを挟むだけである程度の耐バースト性が既に上乗せされます。

したがって、*size*を1・2・4の合計より十分小さい値（目安として、数十KiB以下）に設定した場合、*size*による効果はこれらの「無料の」緩衝地帯に埋もれてしまい、実際にはほとんど体感できません。*size*が意味を持ち始めるのは、1・2・4の合計を明確に上回る大きさを指定したときです。カーネルパイプの容量には（`pipe-max-size`のような）上限があり、拡張には特権やシステム設定の変更を要することがありますが、*size*は（総物理メモリの80%という上限はあるものの）ユーザー権限だけで事実上いくらでも大きくできる点が、このコマンドの存在意義です。

参考として、Linux（本コマンドの開発・検証環境）における実測値は次のとおりでした。

| 緩衝地帯 | 容量の目安 |
|---|---|
| カーネルパイプ1本あたりのデフォルト容量 | 65536バイト（64KiB） |
| カーネルパイプ容量の上限（`pipe-max-size`） | 環境依存（検証機では1048576バイト＝1MiB） |
| stdioの標準入力バッファー（`st_blksize`基準） | 4096バイト（4KiB） |

これらの数値はOSやカーネルの設定に依存し、POSIX規格で保証された値ではありません。他のUNIX系OSでは異なる（特にBSD系やmacOSでは、より小さい）場合があります。

自分の環境での値を確認する簡単な方法は次のとおりです。

* このコマンド自身の`-i`オプション（[後述](#-i)）を使う。Pythonなどの処理系が入っていない環境でも、このコマンドさえビルドできれば確認できます。
  ```sh:
  $ surgetk -i
  ```
* Linux限定・カーネルパイプの実際の容量を調べる（Python 3.10以降、`fcntl`モジュールが`F_GETPIPE_SZ`に対応している環境）:
  ```sh:
  $ python3 -c "import os,fcntl; r,w=os.pipe(); print(fcntl.fcntl(w, fcntl.F_GETPIPE_SZ))"
  ```
* Linux限定・カーネルパイプ容量の上限を調べる:
  ```sh:
  $ cat /proc/sys/fs/pipe-max-size
  ```
* 多くのPOSIX準拠OSで共通・`PIPE_BUF`（アトミックな書き込みが保証されるサイズ。カーネルパイプの実際の総容量そのものではなく、それより小さいか等しい、より限定的な値であることに注意）を調べる:
  ```sh:
  $ getconf PIPE_BUF /
  ```

## オプション

### -s, -o, -d

リングバッファーが満杯になった状態で新しいバイトが到来した場合の挙動を指定します。三つは互いに排他的であり、複数指定した場合は最後に指定したものが有効になります。

* `-s` ... （デフォルト）suspend。バッファーに空きができるまで、標準入力からの読み込みを一時停止（ブロック）します。
* `-o` ... overwrite。最も古い未出力のバイトを破棄し、新しいバイトで上書きします。
* `-d` ... disconnect。その時点でバッファーに残っている未出力のバイトを一切出力せず、このコマンド全体を直ちに終了します。

  ただし、このコマンドは到来したバイトを可能な限り即座に出力する（*time*が常に0であるため）ので、`-d`が発動するよりも前に、既にいくつかのバイトが標準出力に送られ終えている可能性があります。`-d`が保証するのは「発動した時点でバッファーの中に残っていた（まだ送り出されていなかった）バイトを捨てる」ことであり、「このコマンドが一切何も出力しない」ことではない点に注意してください。

### -v

冗長モードレベルを1つずつ上げます。`-v`ならレベル1、`-vv`ならレベル2とし、レベルが高いほど内部動作を詳細に標準エラー出力へ実況します。

レベル1では、少なくともバッファーが満杯になった（溢れた）際に、そのことと今回の対応（一時停止・上書き・切断のいずれか）を毎回報告します。

### -m fd|file

リングバッファーの現在の使用量を、求めに応じて報告します。報告先として、書き込み用に既に開かれているファイルディスクリプタの番号、またはファイルパス（存在しなければ新規作成されます）のいずれかを指定します（[oobleck(1)](oobleck.man.ja.md)の`-d fd|file`と同じ流儀です）。

ファイルパスを指定した場合、既にそのファイルが存在していれば、既存の内容は保持され、新しい報告行はその末尾に追記されます（タイムスタンプ付きのログデータであるため、中身を消して先頭から書き直すことはありません）。

このオプションを指定した状態でこのコマンドが`SIGUSR1`を受信するたびに、その時点の状態を表す1行

```
<UNIX時刻> <自分自身のPID> <使用中バイト数> <容量>
```

（半角空白区切り、容量もバイト単位。UNIX時刻はミリ秒精度で、小数点以下は常に3桁固定で出力されます。例: `1759381200.123`）を報告先に書き込み、直ちにフラッシュします。このオプションを指定しない限り報告は一切行われず、指定した場合でも`SIGUSR1`を受信しない限り自発的に何かを書き込むことはありません。あくまで要求駆動です。定期的に報告させたい場合は、利用者自身が`SIGUSR1`を定期的に送ってください。例えば次のようにします。

```sh:
$ while sleep 1; do kill -USR1 "$PID"; done
```

2列目は、このコマンド自身のPIDです。`-m`の報告先ファイルは`O_APPEND`で開くため（[前述](#-m-fdfile)）、複数のsurgetkプロセスが同じファイルを報告先として共有しても、互いの書き込みが競合したり壊れたりすることはありません。2列目のPIDを見れば、1つのファイルに混在して出力された各行が、どのsurgetkプロセスのものかを区別できます。

標準入力からの読み込みが長時間止まっている（＝`-v`の実況すら出ない）状態でも、`SIGUSR1`を送れば直ちに報告が得られます。これは、このオプションのために専用に用意した監視スレッドが、シグナル到来を`sigwait()`で待ち受けているためです。

ただし、報告の取得にはリングバッファー保護用のロックが必要なため、ちょうど出力側のスレッドがロックを保持したまま低速な標準出力への書き込み処理でブロックしている瞬間に`SIGUSR1`を送った場合、そのブロックが解消されるまで報告の書き込みがわずかに遅延することがあります（データの整合性には影響しません）。

### -i

調査（investigation）モードです。このオプションを付けて実行すると、サージタンクとしての動作は一切行わず、代わりにこのコマンドの周囲を1バイトが通過する際に経由する、各種OS/libcバッファーのサイズ（[前述](#sizeを小さくすることの意味について)を参照）を調査し、標準出力に出力して直ちに終了します。他のオプション（`-s`/`-o`/`-d`/`-v`）や*size*引数はすべて無視されます（*size*は指定する必要すらありません）。

出力形式は、1種類のバッファーにつき1行、1列目に名称、2列目にバイト単位のサイズを半角空白で区切って並べたものです。2列目（サイズ）は右端揃えになります。名称は次のいずれかです（実行環境によっては、調査できなかった項目の行が出力されないことがあります。エラーではありません）。

* `pipe_default_size` ... カーネルパイプ1本あたりのデフォルト容量（Linux限定）
* `pipe_max_size` ... カーネルパイプ容量の上限（Linux限定）
* `stdio_buf_size` ... stdioがパイプに対して使う標準入力バッファーのサイズ
* `pipe_buf` ... `PIPE_BUF`（アトミックな書き込みが保証されるサイズ）

### -h

Usageや最終更新日、ライセンスなどを標準エラー出力に表示します。

## 戻り値

標準入力がEOFに達し、バッファーの内容をすべて出力し終えて正常終了した場合は0を返します。`-d`オプションの効果によりバッファー満杯を理由に強制終了した場合は1を返します。それ以外の異常終了（引数エラーなど）の場合は0以外を返します。

## 使用例

瞬間的に大量のデータを吐き出すコマンド（例えば`yes`）からの出力を、64キビバイトのサージタンクで吸収しつつ、そのまま次のコマンド（"COMMAND1"）へ送る。（COMMAND1側の処理が一時的に遅れても、64KiB分まではデータが失われない）

```sh:
$ yes | surgetk 64KiB | COMMAND1
```

バッファーが4バイトしか無い状態で高速にデータが到来した場合に、古いデータを捨てながら（`-o`）、捨てたことを実況（`-v`）する。

```sh:
$ yes | surgetk -o -v 4B | head -c 20
```

MQTT経由で到来するデータを[mosquitto_sub(1)](https://mosquitto.org/man/mosquitto_sub-1.html)コマンドで受信し、それをパイプ経由で"COMMAND1"に送り処理をさせたい。しかし、時々、COMMAND1の処理能力を超えた速度でデータが到来し、そのままでは取りこぼす恐れがある。そこで、surgetkコマンドを仲介させ、1メビバイト分の入力データを保持できるバッファを確保する。こうすることで1メビバイトまではMQTTデータを取りこぼさないように対策をする。もし、それでもバッファが溢れてしまった場合には、エラー終了して、処理を中断する。

```sh:
$ mosquitto_sub -t MY_TOPIC -h BROKER | surgetk -d 1MiB | COMMAND1
```

[linets(1)](linets.man.ja.md)でテキストデータの到来日時を記録する際、後続のコマンド（"COMMAND1"）の処理能力が低いとやがてその影響がlinetsコマンドに及び、linetsコマンドが入力をブロックしてしまって正確な到来日時が記録できなくなる。そこで、linetsコマンドの直後に大き目（この例では100MiB）のバッファーを確保して、linetsコマンドが入力データをブロックすることを防ぐ。

```sh:
$ cat FAST_DATA_SOURCE_VIA_NAMED_PIPE | linets -3 | surgetk -d 100MiB | COMMAND1
```

surgetkのリングバッファーの使用状況を、パイプラインの途中に挟んだまま`/tmp/mon.log`に対して`SIGUSR1`経由で確認する。パイプラインの中間に置いたコマンドのPIDは`$!`では取得できない（`$!`が返すのはパイプラインの最後のコマンドのPIDのため）。そこで、`sh -c`で一旦サブシェルを立てて自分自身のPID（`$$`）をファイルに書き出させ、続けて`exec`でそのプロセスの実行イメージをsurgetkに差し替える（PIDは変わらないままプログラムだけ入れ替わる）、という、POSIX準拠シェルで共通して使える方法でPIDを捕捉する。

```sh:
$ PIDFILE=$(mktemp)
$ mosquitto_sub -t MY_TOPIC -h BROKER \
    | sh -c 'echo "$$" >"'"$PIDFILE"'"; exec surgetk -m /tmp/mon.log 1MiB' \
    | COMMAND1 &
$ PID=$(cat "$PIDFILE")
$ kill -USR1 "$PID"
$ cat /tmp/mon.log
1759381200.123 12345 2048 1048576
$ rm -f "$PIDFILE"
```

このコマンドの周囲に存在するOS/libcのバッファーサイズを調べる。

```sh:
$ surgetk -i
pipe_default_size   65536
pipe_max_size     1048576
stdio_buf_size       4096
pipe_buf             4096
```

## 規格への準拠

このコマンドのソースコードはC99、IEEE Std 1003.1-2008（“POSIX.1”）に準拠させてあります。
