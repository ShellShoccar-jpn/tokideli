# 動画ライブ配信のように一定時間データ到達を遅らせて平滑化する

(English version is [here](smooth_out_data_delivery_like_live_video_streaming.info.en.md))

[行単位でデータを遅延出力する方法](delayed_output_line_by_line.info.ja.md)では、単にデータを遅延出力するだけでしたが、ここでは実用的な例を一つ紹介します。それは、IoTデバイスの情報を、インターネット等の到達時間の揺らぎが大きい経路を使って送信したいというケースです。

## 同様の例（動画のライブ配信）

動画のライブ配信を思い浮かべてみてください。通信環境が不安定だと、突然動画がフリーズしたり、早回しになったりします。そこでこの現象を防ぐために、元の撮影時刻から意図的に数秒遅らせて再生する（ここでは「バッファリング再生」と呼ぶことにする）ということがよく行われます。仮に3秒遅らせて再生することにしていれば、到達時間の揺らぎが3秒以下である限り、動画は安定的に再生できるからです。

同様のことが、tokideliに収録してあるコマンドとawk(1)コマンドを組み合わせることで実現できます。

## 想定するモデル

まずは、想定する構成を次に示します。

```
 [電子機器#1]
      |
 (USB-Serial)
      |
      V
+-------------------------------------+
| [IoTホスト#1]                       |
|                                     |
| * cuで電子機器#1からデータ受信      |
| * linesでタイムスタンプ付加         |
| * mosquitto_pub等でMQTT化して送信   |---(MQTT over Internet)---+
+-------------------------------------+                          |
                                                                 |
                                                                 |
                                                                 V
                                                          [MQTTブローカー]
                                                                 |
+-------------------------------------+                          |
| [IoTホスト#2]                       |                          |
|                                     |                          |
| * mosquitto_sub等で受信             |<-------------------------+
| * AWKでタイムスタンプに一定時間加算 |
| * surgetkでバッファリング           |
| * tscatで遅延出力                   |
| * cuで電子機器#2へデータ送信        |
+-------------------------------------+
      |
 (USB-Serial)
      |
      V
 [電子機器#2]
```

シリアルインターフェース（USBシリアル）を持つ「電子機器#1」と「電子機器#2」があり、前者から後者へデータを送ろうとしています。しかし、両者は互いに遠隔地にあります。そこで、両者をそれぞれ「IoTホスト#1」、「IoTホスト#2」に接続し、IoTホスト同士をインターネット上のMQTTブローカーを介してデータ授受をしようと考えました。

この時問題になるのが到達時間の揺らぎです。電子機器#1から#2への到達時間を一律に遅らせる（電子機器#2へのバッファリング再生をする）ことで、到達時間の揺らぎを吸収できるようにします。

なお、その他の条件は次のとおりとします。

* シリアルインターフェースの転送速度は57600bpsとする。
* 電子機器#1から#2への到達を3秒遅らせることにして、3秒までの到達時間の揺らぎを吸収できるようにする。

## バッファリング再生のためのワンライナー

前述のような構成かつ要求を満たすために書くべきワンライナーは次のとおりです。IoTホスト#1,#2についてそれぞれ説明します。

### IoTホスト#1

次のようなコマンドを実行します。

```sh:
$ cat | cu -s 57600 -l /dev/MY_USBSERIAL1 | linets -e6 | mosquitto_pub -l -h BROKER_ADDRESS -t TOPIC_NAME
```

それぞれコマンドの役割は次のとおりです。

* cat(1)コマンド
  * データ授受に関しては何も役割を持っていない。（無害）
  * 直後のcu(1)コマンドを[Ctrl]+[C]で簡単に終了できるようにする目的で、裏技的に書いているだけ。
* [cu(1)](https://pubs.opengroup.org/onlinepubs/7908799/xcu/cu.html)コマンド
  * シリアルインターフェースに繋がる機器とのデータ授受に使う。
  * /dev/MY_USBSERIAL1に「電子機器#1」が繋がっている想定で、そこから57600bpsでデータを受け取る。
* [linets(1)](linets.man.ja.md)コマンド
  * 到来したデータに、行単位でタイムスタンプを付加する。
  * 後で時刻の演算ができるように、-eオプションでUNIX時間で出力する。
  * -6オプションを付けて、マイクロ秒までの精度で出力する。
* [mosquitto_pub(1)](https://mosquitto.org/man/mosquitto_pub-1.html)コマンド
  * 受け取ったデータを、MQTTブローカーに対して送信（パブリッシュ）する。
  * MQTTブローカーアドレスは"BROKER_ADDRESS"、トピック名は"TOPIC_NAME"とする。
  * MQTTパケットとしての送出は行単位とする。（-lオプション）

ポイントは、シリアルインターフェース経由で入ってきたデータに真っ先にタイムスタンプを付けることです。ですので、IoTホスト#1の中の[cu(1)](https://pubs.opengroup.org/onlinepubs/7908799/xcu/cu.html)コマンドの直後に[linets(1)](linets.man.ja.md)コマンドを置くべきです。もし、IoTホスト#2の中でタイムスタンプを付けたら、それは揺らぎを受けた後のものになるので、揺らぎを吸収できなくなってしまいます。

なお、行単位ではなくバイト単位で管理したい場合には、[linets(1)](linets.man.ja.md)コマンドの代わりに[charts(1)](charts.man.ja.md)コマンドを使い、次のようにしてください。

```sh:
$ cat | cu -s 57600 -l /dev/MY_USBSERIAL1 | charts -be6 | mosquitto_pub -l -h BROKER_ADDRESS -t TOPIC_NAME
```

* [charts(1)](charts.man.ja.md)コマンド
  * 到来したデータに、文字またはバイト単位でタイムスタンプを付加する。
  * ここでは、-bオプションを付けているのでバイト単位でタイムスタンプを付加する。
  * 後で時刻の演算ができるように、-eオプションでUNIX時間で出力する。（[linets(1)](linets.man.ja.md)コマンドと同じ）
  * -6オプションを付けて、マイクロ秒までの精度で出力する。（[linets(1)](linets.man.ja.md)コマンドと同じ）

### IoTホスト#2

次のようなコマンドを実行します。

```sh:
$ mosquitto_sub -h BROKER_ADDRESS -t TOPIC_NAME |
  surgetk 22KB                                  |
  awk -v dt=3.0 '
    BEGIN {
      OFMT="%.6f"; OFS="";
      while (getline l) {
        i=index(l," ");
        print substr(l,1,i-1)+dt, substr(l,i);
        fflush();
      }
    }'                                          |
  tscat -e                                      |
  cu -s 57600 -l /dev/MY_USBSERIAL2
```

* [mosquitto_sub(1)](https://mosquitto.org/man/mosquitto_sub-1.html)コマンド
  * MQTTブローカーに対してデータの受信要求（サブスクライブ）をする。
  * MQTTブローカーアドレスは"BROKER_ADDRESS"、トピック名は"TOPIC_NAME"とする。
* [surgetk(1)](surgetk.man.ja.md)コマンド
  * 受信したデータを、バッファーに溜め置き、遅延による入力ブロックが手前のコマンド（ここでは[mosquitto_sub(1)](https://mosquitto.org/man/mosquitto_sub-1.html)）に及ぶのを防ぐ。
  * バッファーサイズは22KBとする。（この値の根拠は[バッファーサイズの決め方](#バッファーサイズの決め方)を参照）
* awk(1)コマンド
  * 各行の先頭にある（[linets(1)](linets.man.ja.md)コマンドが付加した）UNIX時間に、遅延させたい秒数（ここでは3.0秒）を加算する。
* [tscat(1)](tscat.man.ja.md)コマンド
  * 各行の先頭に記されたタイムスタンプに従って、行単位でデータを遅延出力する。
  * -eオプションを付けて、タイムスタンプをUNIX時間として解釈させる。
* [cu(1)](https://pubs.opengroup.org/onlinepubs/7908799/xcu/cu.html)コマンド
  * シリアルインターフェースに繋がる機器とのデータ授受に使う。
  * /dev/MY_USBSERIAL2に「電子機器#2」が繋がっている想定で、そこへ57600bpsでデータを送信する。

なお、IoTホスト#1側で、行単位ではなくバイト単位でタイムスタンプを付加した（[linets(1)](linets.man.ja.md)コマンドの代わりに[charts(1)](charts.man.ja.md)コマンドを使った）場合には、[tscat(1)](tscat.man.ja.md)コマンドに-yオプションを追加してください。これにより、元のデータ1バイトごとに改行が付加されなくなり、正しく復元されます。

## バッファーサイズの決め方

[surgetk(1)](surgetk.man.ja.md)コマンド（[delay(1)](delay.man.ja.md)コマンドも同様）に指定するバッファーサイズ（*size*引数）の目安を決めるために、各パラメーターを次のように定義します。

* 入力されるテキストデータの1行あたりの平均バイト数を*sl*
* 1秒あたりに到来する行数を*nl*
* 遅延させたい秒数を*dt*

この場合、遅延出力のために保持しておかなければならないデータのバイト数*sb*（＝[delay(1)](delay.man.ja.md)/[surgetk(1)](surgetk.man.ja.md)コマンドの*size*パラメーターに指定すべき最低値）は、次の式で計算できます。

```
sb = sl * nl * dt
```

したがって、例えば1行あたり81バイトで毎秒平均50行が到来し、それらを3秒遅延させたい場合、*sb*=12150（約12KiB）になります。

あるいは、入力データの転送速度が*r*bpsである場合、*sb*は次のように計算できます。

```
sb = ( r / 8 ) * dt
```

よって、例えば57600bpsの通信路で到来するデータを5秒間遅延させたい場合、*sb*=36000（36kB）になります。

補足:

* これらの見積もりは理論値であり、実際には転送速度の揺らぎによってこれを上回ることがあるので、若干多めに確保しておく方が安全です。
* [delay(1)](delay.man.ja.md)コマンドに指定した場合、内部ではその16倍（64ビット環境の場合）のメモリ領域を確保しようとするので、ホストの搭載メモリ量に注意が必要です（前述のとおり、[surgetk(1)](surgetk.man.ja.md)コマンドの場合はこの倍率は発生しません）。

## まとめ

データの到達時間（レイテンシー）に揺らぎがある通信路において、遅延の長さをある程度犠牲にしてでもレイテンシーを一定に保ちたい場合、ライブ配信動画のようにバッファリングして一定時間だけ遅延再生させるという対策が有効です。tokideliに含まれる、[charts(1)](charts.man.ja.md)・[linets(1)](linets.man.ja.md)・[surgetk(1)](surgetk.man.ja.md)・[tscat(1)](tscat.man.ja.md)の各コマンドと、awk(1)コマンドを組み合わせることで、それが実現できます。
