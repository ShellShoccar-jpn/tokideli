# CALCLOCK(1)

(English version is [here](calclock.man.en.md))

## 名前

calclock - カレンダー時間とUNIX時間の相互変換

## 書式

```sh:
calclock [+[n]h] [-r] f1 [f2 [...]] file
calclock -d[r] string
```

## 説明

crontab(5)やfstab(5)のような空白区切りのテキストデータ形式のfileを与え、その中の指定列（f1、f2、……で指定）にカレンダー時間（"YYYYMMDDhhmmss[.d]"、"d"は秒未満）または、UNIX時間（"n[.d]"、"d"は秒未満）が格納されているとみなし、その列の右隣にUNIX時間、またはカレンダー時間に変換した列を挿入します。

なお、カレンダー時間とUNIX時間の相互変換にはタイムゾーンの情報が必要ですが、カレンダー時刻については、現在の環境に設定されているタイムゾーン設定のものと見なします。タイムゾーンを明示したい場合には、環境変数TZを設定してください。（「使用例」のセクションを参照）

各種引数・オプションについては別途説明します。

## 引数の説明

### f1, f2, ......

列番号。変換対象の日時データが格納されている列を指定します。最低一つ指定しなければなりません。また、複数指定可能です。1つの指定には、次のいずれかの書式が使えます。

* `n` ... 絶対列番号（1以上の自然数）
* `NF` ... 最終列
* `NF-n` ... 最終列から`n`列手前（`n`は1以上の自然数）
* `a/b` ... 範囲指定。`a`、`b`にはそれぞれ上記3種類のいずれの書式も使え、自由に組み合わせられます（例: `2/5`、`3/NF`、`NF-3/NF`、`NF-5/NF-2`）。`a`と`b`の大小は問いません（自動的に小さい方から大きい方へ並べ替えられます）。
* `0` ... 全列を対象にします。他の指定と混在していても、コマンドライン中のどこかに`0`が現れれば、それだけで全列対象が優先されます。

列範囲の`NF`・`NF-n`は、実際に処理している行ごとの列数（NF）に基づいてその都度解決されます。そのため、同じ列番号指定でも、行によって対象となる実際の列が変わり得ます。

* `a/b`のうち、少なくとも一方に`NF-n`（`n`は1以上）を含む範囲指定の場合、解決した結果の下限が列1未満になると、**エラーメッセージを標準エラー出力に表示してコマンド全体を異常終了**します（`NF`単体を含む場合や、両方とも絶対列番号の場合はこの限りではありません）。
* 一方、単一の`NF-n`指定（範囲ではなく単独指定）が列1未満に解決された場合は、エラーにはならず、その行のその列への変換を静かに行わないだけで、処理は継続します。
* 指定した列番号が、実際の行の列数（NF）を超えている場合はエラーにならず、その行が自動的に延長され（間に入る列は空文字列で埋められます）、末尾に変換結果が追加されます。

### file

データ源となるファイル。省略したり、`-`を指定した場合には標準入力と見なされます。複数指定はできません。

### string

変換対象となるカレンダー時間またはUNIX時間文字列を引数として直接指定するための引数です。-dオプションが指定された場合に設定可能です。

## オプション

### +[n]h

ヘッダー行数指定。列名を記した行など、変換対象日時データの入っていない行が先頭にn行ある場合に、その行を何も加工せずに出力します。nは省略可能で、省略した場合は1と見なされます。また、このオプションそのものを省略した場合は0（ヘッダー行なし）と見なされます。

### -r

逆変換モード。このオプションを指定しなかった場合、指定行に入っているデータをカレンダー時間（YYYYMMDDhhmmss[.d]、dは秒未満）とみなし、UNIX時間（n[.d]、dは秒未満）に変換した列を右隣に挿入するという「正変換」を行いますが、このオプションを指定した場合は、指定行に入っているデータをUNIX時間と見なし、カレンダー時間に変換した列を右隣に挿入します。

### -d

ダイレクトモード。変換対象時刻を引数で直接指定するためのモードです。結果は、`元の時間 変換された時間`という2列で出力されます。

## 環境変数

### LINE_BUFFERED

標準出力のバッファリングモードを指定します。

* `yes` ... 行バッファリングモードにします。
* `forcible` ... 行バッファリングモードにします（`yes`と全く同じ動作です。`yes`の場合との違いは、行バッファリングへの切り替えが不可能なら代わりにエラー終了する、という意味ですが、実際にはこのコマンドが動作するどの環境でも行バッファリングへの切り替えが不可能になることはないため、実用上`yes`と区別する意味はありません）

いずれも指定しなかった場合は、通常のバッファリングモード（端末に接続されていればラインバッファリング、それ以外はフルバッファリング）になります。

## 戻り値

指定されたファイルを正常に処理できた場合にのみ0を戻し、引数やオプション、ファイル、内容の異常により正常に処理できなかった場合には0以外を戻します。

## 注意

### 不正な日時データを変換しようとした場合

変換対象の列に、カレンダー時間・UNIX時間として解釈できない文字列（不正な日付、63以上の秒、範囲外の月日など）が入っていても、エラーにはなりません。その場合、変換結果として`xxxxxxxxxx`という10文字のゴミ値がその場に挿入されるだけで、処理は継続します（このコマンド自身が異常終了するわけではないため、戻り値には反映されません）。

同様に、UNIX時間からカレンダー時間への変換（`-r`指定時）において、UNIX時間の絶対値が1兆（10^12）を超える極端な値の場合も、`xxxxxxxxxxxxxx`という14文字のゴミ値が挿入されます。

なお、秒未満を表す小数点以下の部分（`.d`）は、変換の際に数値として検証されることなく、そのまま文字列として変換結果の末尾に付け足されます。そのため、小数点以下に数字以外の文字が含まれていても、そのまま素通りして出力されます。

## 使用例

元データaccess.logの内容が次のようなものだったとする。

```text:access.log
20220718000000 user1: log in
20220718000010 user1: access "members.cgi"
20220718000030 user1: log out
```

これに対し、1列目のデータをUNIX時間へ正変換（ただしタイムゾーンは日本時間）し、ファイルaccess2.logに格納する。

```sh:
$ export TZ=JST-9
$ calclock 1 access.log > access2.log
```

生成されたファイルaccess2.logの内容は次のとおり。

```text:access2.log
20220718000000 1658070000 user1: log in
20220718000010 1658070010 user1: access "members.cgi"
20220718000030 1658070030 user1: log out
```

## 歴史

このコマンドのオリジナルは、USP研究所によるOpen usp Tukubaiであり、それをPOSIX準拠のシェルスクリプトに移植したものです。機能的には上位互換のはずです。シェルスクリプト版（`cmd_scripts/calclock.sh`）に加えて、同等の動作をするC言語版（`c_src/calclock.c`）も用意されています。

## 規格への準拠

シェルスクリプト版はIEEE Std 1003.1-2001（“POSIX.1”）に準拠したsh向けのシェルスクリプトで書かれており、かつ、呼び出している各コマンドは同規格の仕様の範囲内です。C言語版はC99、およびIEEE Std 1003.1-2008（“POSIX.1”）に準拠させてあります。
